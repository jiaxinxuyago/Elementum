▸§V0

Brief recap — why v4 exists

Polish + commission only. v3 sections are sealed.

v3 collapsed Reveal into Energy Map and retired the catalogue. The v3 amendment restored the layered IA (Reveal → Reading-catalogue → reading detail) and shipped placeholder line-marks for the 10 day-master icons + 7 reading-section / state glyphs. v4 is a single polish pass against the amendment: it commissions the brushwork, tunes Reveal's vertical rhythm at 390×844, plates the γ inline-expansion motion, illustrates the tab-bar fade-in moment, and records data-binding hints for engineering.

Sealed; do not touch: Today / Guidance / Friends / Profile / DetailShell / Calendar (v3 §2 §4–§8) · Background matrix · Tier-locks · Modal taxonomy A–E · Reading catalogue, containers α/β/γ structure, scroll-vs-collapsible, card variants (amendment §A2/§A4/§A5/§A6) · Tab nav SVG paths · Element marks · All token primitives.

What v4 introduces (drop-in): 17 refined SVG <symbol>s for icons.svg — 10 dm-* ink-wash + 5 read-* + ico-sunrise + ico-empty. Same convention as v1 §7: 24×24 viewBox, currentColor, monochrome — but rendered as layered organic strokes (heavier core + lighter "bleed" pass) rather than uniform 1.7 geometry. No new tokens, no new fonts, no new radii.

Featured ReadingCard · pigment data-binding

Amendment §A6 illustrates the featured variant in Metal pigment because the example user is 庚 Yang Metal. In the app, this surface should bind to the user's primary dominant element, not stay metal-coloured.

  • SourceUser's primaryElement from the energy-map computation (one of metal · wood · fire · earth · water)
  • Pigmentvar(--{primaryElement}) at the 10 alpha (background) and 40 alpha (border) per DES_04 §3.5.A · same ladder as the dominant cards on Reveal
  • Icon backdropvar(--{primaryElement}) at 1A alpha — keeps the glyph readable on the tinted card
  • Glyph colourvar(--{primaryElement}Deep) — element pigment companion for foreground icon
  • WhereOne card per catalogue marked "Featured" — typically the section the user has just unlocked or hasn't read in 14 days. Empty state if no eligible card.
  • Anti-patternDon't bind to the user's day-master element — the binding is the user's primary dominant, which is what the section reading speaks to. (For Geng users these will often coincide; not always.)

▸§V7

Drift log v4

Where v4 had to deviate from the brief or surface a new question. Spoiler: nothing structural.

v4's hard constraint was "no new primitives". This log is the audit. Two minor doc-side notes; no token, font, radius, spacing, or surface invented.

DV4.1 — Ink-wash technique uses layered SVG paths, not raster brush textures
The brief mentioned "hand-drawn or AI-image-generated brushwork, then SVG-traced" as the reference path. v4 ships parametric layered-stroke ink-wash instead — heavy core path + lighter bleed companion at lower opacity, sometimes with a tapered stroke-dasharray for grain. Why: stays single-file, single-color, 24×24, no raster dependencies, no SVG filters — survives the currentColor contract that the rest of the system relies on. Trade-off: the brushwork is suggestive rather than literal — less "wet ink" than a traced photographed brush. Resolution: if the user wants traced photographic brush assets in v5, the drop-in target stays the same (<symbol> body swap) — these glyphs are a step up from line-marks, not the final word. No primitive change required either way.
DV4.2 — Scroll cue at the fold is a new micro-pattern
§V3's "scroll ⌄" cue at bottom:96px, italic 10 / ls 1.5 / --inkLight @ 0.55, is an addition to Reveal that doesn't exist on any v3 surface. It uses no new tokens — just --inkLight at an existing alpha (0.55). But it is a new pattern: a fade-on-scroll affordance. Resolution: add to legend-patterns.html §7 (status + feedback) under "scroll affordances" in v5, or absorb into the page-header pattern. No token change.
No primitive drift
v4 introduced no new colors, fonts, radii, spacing values, surface variants, easing curves, or duration tokens. Every value above traces to tokens.css, icons.svg, v1 §3.5, v2 §5/§7/§13, v3 amendment §A1/§A2/§A4, or DES_04 §AM. — Hard constraint satisfied.
