▸§A0

IA stance — Reveal → Reading-catalogue

Overrides v3 §0. Restores the layered reveal model the user locked.

v3 §0 collapses Reveal into the Energy Map dashboard and retires the catalogue pattern. The user's intent (set in this code session, prior to v3 delivery) is the opposite: a layered Reveal → Reading-catalogue → reading detail flow. This amendment restores that IA. v3's flat-dashboard sections that don't depend on the catalogue (Today / Guidance / Friends / Profile / DetailShell / Calendar / Backgrounds / Tier-locks / nav map) remain canonical.

v3 §0 — flat dashboard
  1. Reveal absorbed into Energy Map (mini DM hero + ribbon + forces inline)
  2. Energy Map = persistent dashboard tab; readings inline
  3. Catalogue retired; drill-downs go to DetailShell
  4. Tab bar: Today · Map · Guidance · Friends · Profile
  5. No "Enter Your Readings" CTA
→
Amendment — layered reveal
  1. Reveal is its own surface — identity card + full Energy Map summary, ends in a CTA
  2. Tap "Enter Your Readings" → Reading catalogue page
  3. Reading is a tab; Energy Map is reachable as a button-link from Reading's header
  4. Tab bar: Today · Guidance · Reading · Compat · Profile
  5. "Energy Blueprint" renamed to "Energy Map" (eyebrow on Reveal & Reading)

What carries over from v3 unchanged: Today (§2) · Guidance (§4) · Friends (§5) · Profile (§6) · DetailShell (§7) · Calendar & year timeline (§8) · Background matrix (§9) · Tier-lock pattern (§10) · Modal taxonomy A–E (§11) · Cross-screen nav map (§12). All compose from v1+v2 atoms; the amendment doesn't touch them.

What this amendment supersedes: v3 §3 Energy Map's framing as "the home tab with readings inline" — Energy Map becomes a destination from Reading, with the same content density. The amendment's §A1 Reveal IS the Energy Map first-time experience.

Why placeholder

The user's brief asks for ink-wash style — painterly brush dynamics, ink bleed, irregular edges (sumi-e influence). These can't be produced cleanly as parametric SVG without source brush textures or trace-from-image. The line marks above match v1 §7's existing element-mark vocabulary, so the system stays visually consistent until painted assets arrive. Replacement strategy: commission 10 hand-drawn brush marks (ink on rice paper photographed and traced, or AI-image-generated and SVG-vectorised), keep 24×24 viewBox + currentColor + 1.7 stroke convention, swap inline. Each .ink-mark svg is the single drop-in target.

▸§A7

Drift log · amendment

Where the amendment diverges from v3 or v1+v2 are silent. Each item awaits an owner answer.

Items where the amendment had to deviate, document a known gap, or call for a follow-up commission. Together with v3 §14, these accumulate the punch list for v3.5 / v4.

DA.1 — IA divergence with v3 §0
v3 §0 retires the catalogue and lifts readings inline onto Energy Map (a flat dashboard). The user's locked direction is the layered Reveal → Reading-catalogue model (this amendment). Resolution: the amendment is canonical for Reveal / Reading / Energy Map; v3's flat-dashboard framing is superseded for these three surfaces. v3's other sections (§2, §4–§8, §10–§12) carry over unchanged. DES_04 §11 needs a doc patch reflecting the layered IA.
DA.2 — Day-master ink-wash icons are line-mark placeholders
§A3 ships 10 line-mark icons in v1 §7's style (1.7px stroke · currentColor · 24×24). The brief's "ink-wash" intent (sumi-e brush dynamics, ink bleed, irregular edges) requires hand-drawn or AI-image-generated assets traced into SVG. Resolution: commission 10 brush-drawn marks; swap inline at .ink-mark svg. Until then, the line-marks are visually consistent with the rest of the system but read as "geometric icons" rather than "ink-wash glyphs".
DA.3 — Tab label naming inconsistency in v3
v3 §0's BEFORE/AFTER table names the tabs Today / Map / Guidance / Friends / Profile, but every phone-frame mock in v3 (§2 Today, §3 Energy Map, §5 Friends) renders the bar as Today / Guidance / Reading / Compat / Profile. The amendment locks the rendered names — Reading at center (carrying the seal-dot indicator) and Compat for compatibility. Resolution: patch v3 §0 to match the rendered mocks.
DA.4 — Reveal / Energy Map content overlap
Reveal (§A1) and the Energy Map destination accessed from Reading both render identical content (DM hero + identity ribbon + dominant + catalyst/resistance + …). The difference is framing: Reveal ends with the "Enter Your Readings" CTA; the destination Energy Map ends with "‹ Reading" back-nav (or no footer). Resolution: intentional. The repeat is the point — Reveal is the first-time view, Energy Map is the return view. They share a single component (EnergyMapBlock) with a footer-mode prop.
DA.5 — γ inline-expansion needs a height-transition primitive
DES_04 §4 covers ease curves for screen entrances, list reveals, and tab transitions, but not max-height animations. §A4 γ uses max-height: 90 → 340 / 220ms / ease-out. Resolution: document this as a "card-expand" motion in DES_04 §4 alongside chev rotation. No new primitive — same ease curve as scroll-triggered reveals.
DA.6 — Reveal Cormorant title weight
v1 §2 anti-pattern says "archetype titles ✗ bold" — keep at 400. The amendment's Reveal hero uses Cormorant 34/400 for "The Steady Blade", consistent with v1. v3 §3's mini-DM-hero uses Cormorant 24/600 — heavier because at smaller size, but inconsistent on the "never bold" rule. Resolution: at hero scale (≥30px) keep weight 400; at mini-hero scale (≤24px) weight 500–600 is acceptable. Codify in v1 §2.
DA.7 — Empty card variant introduces a new "placeholder" pattern
§A6's Empty variant uses a 1px dashed border + italic --inkLight copy + faded glyph. v1 §3.5.F dashed-border rule is "interaction affordance only — never used as a static separator". Empty cards aren't separators, but they aren't tappable either — they're placeholders. Resolution: re-scope v1 §3.5.F: "dashed borders are reserved for interaction affordances or placeholder/scaffolding states. Static separators stay solid 1px --paperHair."
DA.8 — "Energy Map" eyebrow on Reveal vs Reading link label
On Reveal, the section eyebrow reads "ENERGY MAP" (capitalised, the renamed "Energy Blueprint"). On Reading, the right-side action also reads "Energy Map →". Identical label, two different surfaces — minor but worth a single-source-of-truth string. Resolution: add a copy lock: STRINGS.ENERGY_MAP = "Energy Map", used in eyebrow and link both. Future v4 i18n handles localisation from one key.
DA.9 — Reading-section icon library doesn't exist in v1+v2
Restoring the catalogue introduces five reading-section icons + an Empty-state mark that were never iconographied. v1 §7 + v2 §11 commissioned five element marks, one lock icon, and five tab-nav icons — they cover the chrome (tabbar) but not the catalogue content.

Amendment ships line-mark placeholders grounded in v1's geometric vocabulary (1.7px stroke · currentColor · 24×24 viewBox):
• Elemental Nature → wu-xing pentagram (circle + inscribed 5-vertex polygon)
• Dominant Energies → primary filled + secondary hollow circles (size hierarchy = role hierarchy)
• Forces in Motion → ↑↓ arrow pair (catalyst lifts, resistance pushes)
• Life Chapters → vertical stem + 3 horizontal branches (decade timeline)
• Pillar Patterns → 4 vertical bars (the literal 八字 four pillars — defined but not rendered; locked card shows lock icon instead)
• Daily compact → sun + horizon line (sunrise = today)
• Empty placeholder → circle + 3-dot ellipsis (vessel-not-yet-filled)

Tab icons (Today / Guidance / Reading / Compat / Profile) are not placeholders — the amendment's tabbar (§A2) is now byte-identical to legend-screens.html §4's canonical SVG paths. Reading uses the curved-spine open-book glyph, Guidance uses the leaf-in-circle, Compat uses the two-overlap circles, etc. Earlier amendment drafts diverged here; resolved.

Resolution for the section icons: commission domain-specific brushed/painted versions or refine geometry on Claude Design's next pass. Single drop-in target: .icbox svg in §A2 / §A6 (catalogue). Companion task to DA.2 (day-master ink-wash icons) — same root cause: asset library lags behind surface coverage.
DA.11 — Italic usage v2 cascaded (DES_04 §AM.10)
v1 §3.5.E originally allowed italic across 5 contexts (sub-headline, element-name label, composition row name, descriptive paragraph, microcopy). The new rule (sealed in legend-primitives.html §8 v2 + DES_04 §AM.10, dated 2026-05-06) restricts italic to two contexts only: sub-headline and microcopy. Resolved in this amendment: CSS rules for .ribbon .elname, .read-card .body .d, .read-card.daily .body .t, .dm-icon-cell .meta-l, .inline-card .pre, plus inline reading copy in §A4 α & β — all reverted from italic to regular. The "Precision before intention" sub-headline on Reveal (§A1) and the microcopy chips remain italic per the v2 rule. Open: the v2 patterns legend (legend-patterns.html) and v3 screens legend (legend-screens.html) still contain italic uses on now-forbidden contexts — those are flagged for v4 polish.
DA.10 — Tab nav is icons-only (labels removed)
v2 §4 + v3 §4 spec the bottom tab nav with text labels under each icon (EB Garamond 11 / 500 / ls 1.6 / uppercase / --inkLight). The amendment removes labels — the tabbar carries icons only, with the Reading tab's seal-dot indicator sitting directly beneath the active icon. Rationale: cleaner chrome; relies on the 5 icons being legible on their own (calendar, leaf-in-circle, open-book, Venn, person); reduces vertical chrome density inside the phone frame; matches Pattern/Nebula reference apps' labelless bottom-nav idiom. Trade-off: first-time discoverability — onboarding may need a one-time tooltip / coachmark per tab. Resolution: the amendment locks this as the canonical app tab style going forward. Patch v2 §4 + v3 §4 to remove labels in their next revisions.
