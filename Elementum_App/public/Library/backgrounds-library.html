§E

Composition + opacity guidance

Rules of thumb for picking opacity and composition when generating new bgs or wiring an existing variant.
Opacity by negative-space ratio:
  • < 30% NS (reading catalogue, energymap with diagram) — opacity 0.10–0.15; bg recedes hard, foreground dominates
  • 30–50% NS (energymap detail, onboarding) — opacity 0.13–0.30; bg supports without competing
  • 50%+ NS (welcome, loading, reveal panels, reading detail) — opacity 0.30–0.50+; bg fills negative space organically
Composition by slot semantic: filenames carry intent. -corner-stamp wants a corner-weighted painting (crop=right or left). -edge-band wants horizontal weight at top (crop=top). -bottom-anchor wants weight at bottom (crop=bottom). -mist-veil wants atmospheric softness with no dominant subject. -center-glow wants radial atmosphere. Honour the semantic; don't fight it.
CSS multiplier compensation: when a component applies CSS opacity or mixBlendMode: multiply on top of the bg image, the source PNG's opacity must be bumped to compensate. Example: bg-reveal-02 has CSS opacity: 0.6 + multiply, so its source opacity is 0.65 to land at ~0.39 effective on the canvas. Always check the consuming component before setting source opacity.
Cream-silk gradient base (constant): top #F2E8CF → bottom #E2D8B9, vertical linear gradient. Every bg in this library uses the same base under the painted layer, so the system reads as one coherent paper across pages. Never invent a new base color.
Format invariants (sniff tests):
  • Always 32bpp ARGB PNG at exactly 390×844
  • File size: 150–400 KB typical
  • Saved at Design/assets/backgrounds/<file>.png
  • Mirrored to Elementum_App/public/assets/backgrounds/<file>.png when consumed by app code
